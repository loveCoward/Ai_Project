## 1. 目标、使用者与范围

### 1.1 目标与成功含义 [已确认：原文、Q1-Q2]

面向中小型 B2B 软件/IT 解决方案团队，使用固定的“中型制造企业采购企业 AI 工作流平台”场景，展示可本地运行、可复现、可评测的售前工作台。实际操作人是售前团队，不是制造企业终端客户。

核心产出是带证据、风险、待澄清事项和审阅记录的方案包。系统辅助业务判断，不自动替人承诺产品能力、报价、交付日期或合同义务。可信地识别“不支持”同样是分析成功，不能靠虚构支持来提高覆盖率。

### 1.2 首版范围 [已确认：原文、Q3-Q10、Q35、Q38、Q42]

| 范围 | 首版内容 |
| --- | --- |
| 产品 | 企业 AI 工作流平台：知识库、流程编排、权限、私有化部署、系统集成 |
| 输入 | 有可提取文本的 PDF、DOCX，以及 Markdown、JSON；逐文件报告结果 |
| 输出 | 统一结构化 JSON，以及由其渲染的 Markdown/HTML 方案包 |
| 人机协作 | 运行、查看节点和证据、编辑结构化草稿、审阅、审批、导出、恢复 |
| 数据与角色 | 单租户，销售/售前架构师/审核人，三个预置演示账号，JWT 与后端授权 |
| 知识与记忆 | 版本化知识库、受限检索、商机/客户边界内的有来源记忆 |

### 1.3 明确不做 [已确认]

扫描件 OCR；正式 DOCX/PDF 文件生成；多租户及复杂权限管理；企业 SSO；真实 CRM/飞书/钉钉连接器；合同与正式报价系统；无人审批外部写入；Agent 无限递归、自改提示词/代码/流程、线上策略自动优化；生产并发/SLA 承诺；单独的脱敏版本发布工作流。

禁止用 Stub 结果证明真实 Agent 能力，禁止隐藏模型切换、权限绕过、缺失证据、关键失败或部分发布。

| 已比较方向 | 已选择 | 放弃方向与原因 |

## 2. 角色、权限与数据边界

### 2.1 操作权限矩阵 [已确认：Q5、Q13、Q22、Q28、Q32]

每次操作同时校验身份、角色、当前数据范围和业务状态。单有角色权限不代表可以读取所有商机或文档。前端隐藏按钮不构成权限控制。

| 操作 | 销售 | 售前架构师 | 审核人 |
| --- | --- | --- | --- |
| 查看商机和方案 | 授权范围内 | 授权范围内 | 授权范围内 |
| 创建本地任务、上传客户材料 | 否 | 是 | 不作为首版职责 |
| 发起分析、编辑草稿、关联证据 | 否 | 是 | 不直接代改方案 |
| 提交审阅、任务创建请求、写入清单 | 否 | 是 | 审阅其请求 |
| 批准/退回方案及外部动作 | 否 | 否 | 是，禁止自审批 |
| 上传/提交内部知识候选版本 | 否 | 是 | 审核发布 |
| 批准知识发布、替换、停用 | 否 | 否 | 是 |
| 修改已批准方案正文 | 否 | 否，需新版本 | 否，需新版本 |

**[已批准 P02]** 销售可导出其有权读取的正式方案；架构师和审核人可导出有权读取的草稿及正式方案，草稿必须标记。取消/重跑由架构师发起；发布恢复由审核人触发，仍需重新校验当前授权。首版不建立用户/角色/ACL 管理控制台，演示账号和数据归属通过本地配置及种子数据定义。JWT 秘钥、账号密码和 API Key 不入库。

### 2.2 来源与派生物的权限 [已确认：Q23、Q36、Q43；实施细则已批准 P02]

- 客户材料归属于明确的商机或任务；内部知识可跨任务复用，但不能跨越授权。客户级记忆不自动扩散成全局知识。
- 向量和关键词两路候选检索都硬过滤权限；禁止先把受限候选送给模型再要求其不引用。
- 方案、导出、记忆、缓存结果和轨迹均不是权限洗白通道。已批准内容仍受来源限制。
- **P02 已批准**：整个派生物采用保守的交集策略，用户须同时有权访问派生物归属对象及所有实际输入来源；不是仅看最终显示的引用。未知来源/权限缺失时拒绝访问。
- **P02 已批准**：每次读取、导出、恢复、工具写入重新验权。权限收紧后禁止继续访问旧派生内容；保留审计关联但不泄漏受限原文。已下载的离线文件无法远程撤回，界面应提示此局限。
- **P02 已批准**：商机备注和 MCP 中的正式记录必须继承相同限制；若目标不能承载对应限制，不执行该动作并显示待处理，不能为了发布成功自动降级权限。
- **P02 已批准**：固定演示包含同角色不同商机授权，以及销售无权查看某份内部安全资料两个反例，不仅演示按钮差别。

### 2.3 真实服务调用边界 [已确认：Q9、Q20、Q36、Q42；已批准 P02/P09]

工程测试不调用真实模型。真实演示与能力评测仅在显式选择后调用配置的真实兼容 API 或本地 LLM；失败不静默换 Fake。无配置时可以明确选择离线演示，结果必须标注模式。

**P02 已批准**：上传时要求材料来源和使用授权声明，不承诺自动识别所有敏感信息。首版拒绝用户声明为真实客户敏感的数据；无法确认来源的材料进入待补充而非发往服务。真实环境数据治理不在首版能力声明内。

**P02 已批准**：出站接收方来自用户明确配置的端点，不接受模型/文档提供的临时目的地址；Embedding、Reranker、Judge 和观测同样适用。外部观测默认关闭或仅发不含客户正文/证据内容的必要元数据，不记录 Key、JWT 或密码。合成也不意味着忽略演示 ACL。

## 4. 主流程与状态转换

### 4.1 端到端过程 [已确认：原文、Q12、Q21、Q30-Q31、Q44]

1. 架构师选择有权访问的商机，创建本地任务，上传合规材料。
2. 逐文件解析并形成输入清单，必要时等待补充。
3. 在当前工作区进行需求拆解、证据检索、专业分析与初步方案准备。
4. 架构师提交外部任务创建请求；审核人批准精确动作后通过 MCP 创建外部记录。创建任务不代表批准方案。
5. 架构师处理证据、冲突、风险和澄清事项，编辑并提交完整方案包。
6. 审核人针对固定内容快照审阅，批准、退回或拒绝；高风险接受须明确记录，严重风险不能豁免。
7. 批准的动作集合逐项执行，结果未知先核实，失败保留成功项并进入恢复。
8. 动作全部确认成功才显示发布完成；允许继续查看已批准但发布未完成的内容，并显著区分其状态。

### 4.2 任务、版本、运行、发布不得混用

**[已确认]** 任务和版本有各自状态，运行可失败而已有草稿仍存在，方案可已批准而发布仍未完成。

**[已批准 P01：完整转换细则]** 为避免把“生成完但尚未提交”误称“待审阅”，任务补充“已分析待提交”。发布状态独立附着于相应版本，不覆盖任务的业务批准事实。下面未列出的跳转默认拒绝。

| 任务当前状态 | 事件/条件 | 目标状态 |
| --- | --- | --- |
| 新建、待补充、失败、已分析待提交 | 架构师启动，关键输入有效且无其他活跃尝试 | 分析中 |
| 新建、分析中 | 关键材料不足/无法解析 | 待补充 |
| 分析中 | 分析结束、结构校验通过并保留降级说明 | 已分析待提交 |
| 分析中 | 不可继续且非材料缺失 | 失败，保留部分结果 |
| 已分析待提交、待补充 | 架构师提交；输入/审批门禁通过，外部任务已成功创建 | 待审阅 |
| 待审阅 | 架构师撤回且尚未批准 | 已分析待提交；版本转草稿，原待审批请求失效 |
| 待审阅 | 退回或拒绝当前版本 | 待补充，区分版本结论 |
| 待审阅 | 审核批准当前快照及指定动作 | 已批准；发布状态为待执行 |
| 已批准 | 动作全部确认成功 | 已完成 |
| 已批准 | 动作部分失败/结果未知 | 仍为已批准；发布未完成/待恢复 |
| 已批准 | 审核人终止无法安全继续的发布、停用受影响版本，且全部在途/未知动作已核实 | 待补充；旧发布保留为已终止且未完成，不标记成功 |
| 新建、分析中、已分析待提交、待补充、失败、待审阅 | 架构师取消；尚未正式批准 | 已取消，禁止新外部副作用 |
| 已批准、已完成 | 发起实质性修改 | 建立新方案版本与修订流程；旧版本/发布状态保留 |
| 已取消 | 再次开展同类工作 | 新建任务，不复活取消前的审批 |

**P01 已批准**：任务状态反映当前工作版本，不能覆盖历史批准版本的状态。新修订进入分析中或已分析待提交，原批准版照常保留；已批准但尚未完成发布的版本，先完成其待恢复动作，或按 P04 终止剩余发布并核实全部在途动作，再启动实质性新修订，避免多组外部副作用竞争。每次状态转换记录执行人、事件、时间和目标修订。

| 版本当前状态 | 事件 | 后续处理 [P01] |
| --- | --- | --- |
| 草稿、需修改 | 编辑 | 递增内容修订，保留旧修订及操作者 |
| 草稿、需修改 | 提交且所有门禁通过 | 待审阅，锁定该内容快照 |
| 待审阅 | 审核退回 | 需修改；原提交快照和评论保留 |
| 待审阅 | 架构师在批准前撤回 | 草稿；任务同步回到已分析待提交，旧待审批请求失效 |
| 待审阅 | 审核拒绝 | 已拒绝；再提案创建新候选版本 |
| 待审阅 | 审核批准 | 已批准；正文和证据快照不可覆盖 |
| 已批准 | 新版本批准并发布完成 | 旧版本标记已替代，作为已废弃的原因；保留历史可审计内容 |
| 已批准 | 发现承诺/证据失效 | 审核人停用并记录原因；不能原地修正文案 |

**P01 已批准**：待审阅时不能直接编辑，先撤回为草稿并失效原待审批请求。拒绝、停用不删除审计。分析运行期间禁止并行编辑其输入快照；可取消后修改再运行。任何旧尝试、取消尝试不得覆盖当前候选版本或恢复旧审批。

### 4.3 外部任务创建与发布恢复 [已批准 P04]

外部任务创建另有“未请求/待批准/已批准待执行/已创建/失败或未知”状态，不以任务“已批准”冒充创建批准。输入材料、本地草稿、内部审计写入不是 MCP 外部创建操作。系统记录审批决定本身不需要递归审批；将审阅结论同步到外部工作区才属于批准清单中的动作。

每项动作绑定批准人、提交人、对象、参数、版本、权限范围和幂等身份。执行前仍需当前授权；原批准人无权时暂停，由另一名当前授权审核人重新批准，不能借历史批准绕过撤权。

参数不变且权限/业务门禁仍有效时，可以恢复同一批准清单；已成功项不重放，失败项有界重试，未知项通过目标记录/幂等身份核实后处理。不提供“忽略失败并完成”按钮，也不宣称跨系统全局回滚。

**P04 已批准**：动作依赖顺序为外部任务存在 -> 保存正式版本 -> 关联审阅结论/商机备注。未成功创建目标记录时不能执行其子动作。批准清单由提交方显式选定，审核确认后不得悄悄删除失败项以冒充完成。

**P01/P04 补充规则，已批准**：证据失效、业务门禁失败或目标无法保留必要权限，导致原发布不能安全继续时，允许当前有权审核人选择“终止剩余发布”，填写原因并停用受影响版本。未执行动作标记为已终止，已成功动作保留其事实；旧批准和旧清单留存但不得继续授权执行。终止不等于回滚、任务取消或发布成功。未知/在途动作仍须核实，未核实前不启动会竞争同一业务对象的新修订发布；全部核实且无在途动作后可建立新候选版本。新版本及补救写入需重新审批，不自动撤销或覆盖已经产生的外部效果。此出口防止“旧版不安全而不能继续，又因未发布完而不能修订”的死锁。

## 5. 需求覆盖、证据、风险和澄清

### 5.1 覆盖判定与分母 [已确认：Q14、Q24、Q33、Q41]

| 状态 | 含义 | 是否计入完全覆盖分子 |
| --- | --- | --- |
| 已覆盖 | 有适用能力证据，无未解决关键限制 | 是 |
| 部分覆盖 | 支持部分内容，有明确缺口/限制 | 否 |
| 未覆盖 | 当前方案没有满足该需求，不等于已证明产品永远不能支持 | 否 |
| 待澄清 | 需求含糊、证据不足或冲突妨碍判断 | 否 |
| 不在产品范围 | 已确认属于产品能力边界之外 | 否，但仍在分母内 |

业务覆盖率 = 完全覆盖的需求数 / 当前客户确认范围内的需求总数。并列展示其余状态数量，不将部分覆盖擅自折算满分。

必须需求处于未覆盖、待澄清、不在产品范围时不能正式批准；部分覆盖需审核人明确接受风险，且不能绕过严重风险门禁。审核人不能单方删除客户必须需求来提升分数；范围调整需要客户确认依据。

**[已批准 P03]** 重复需求合并须保留每条原始来源；未确认合并不改变分母。范围为空时覆盖率显示“不适用”，禁止宣称 100% 或提交正式方案。拆分/合并粒度固定在对应客户需求基线中，评测与版本比较使用同一基线。

例：确认范围有 10 条，6 条已覆盖、2 条部分、1 条待澄清、1 条范围外，业务覆盖率是 60%。若后两项为必须需求，方案不能批准；若 Agent 正确识别全部十条及其限制，其分析质量可以很高，不应逼它虚报 100% 产品匹配。此例为说明，不是项目实测数据。

### 5.2 冲突和澄清 [已确认：Q6、Q15、Q25、Q27]

证据缺失标明不足；冲突保留各版本、适用范围、来源和分析意见。架构师可以提出处理建议，影响正式结论的冲突需要审核人确认。审核人确认的是有证据的处理方式，不是有权把矛盾事实任意改真。

**[已批准 P03]** 澄清记录由架构师录入回答、回答者、确认时间和来源；关键客户确认无来源时仍未解决。非关键问题可以带条件保留，关键需求/关键证据不明确则阻断提交。答案变更触发受影响需求、风险和版本复核，不能静默更新已批准版本。

### 5.3 风险与正式批准门禁 [已确认：Q16、Q26、Q33、Q39、Q41]

风险类别：安全合规、部署、集成、数据、交付、产品能力。每项保留等级、依据、影响、缓解、责任人和处置决定。

| 等级 | 已确认的处理 |
| --- | --- |
| 严重 | 阻止正式批准，不允许普通风险接受替代解决 |
| 高 | 审核人明确接受残余风险或要求缓解 |
| 中 | 记录处置措施 |
| 低 | 可作为交付注意事项随方案发布 |

**[已批准 P03]** 严重风险指会造成明确违反硬性约束、重大安全暴露或无可行交付路径的情形；高风险指方案仍可行但关键目标受明显威胁；中低风险按影响和可控性分级。模型建议、人工改级及其依据均留痕；没有新证据/缓解验证，不能仅为过门禁降级。

正式审阅提交前检查：关键材料有效；必需章节与证据可定位；必须需求满足门禁；关键冲突已解决；严重风险已消除；中风险有处置；不存在未经确认的绑定报价/日期/合同承诺；提交快照与操作者权限有效。高风险和必须需求部分覆盖的接受决定在审核批准时补齐，否则不能批准。

## 6. 知识、记忆与历史可追溯性

### 6.1 知识治理 [已确认：Q17、Q32；已批准 P05]

内部文档从候选上传、解析/索引到审核发布；未批准候选不能作为已发布知识参与正式分析。客户上传材料是当前任务输入，不要求伪装成内部已发布知识；其来源和权限独立管理。

**P05 已批准**：当前有效版本按文档系列和产品/部署适用范围确定，不简单用上传时间覆盖其他产品分支。替换只在审核通过且新索引可用后切换，失败保留原有效版本。知识停用立即从新检索排除，旧版受限保留用于审计，不提供普通用户硬删除和自动历史重写。

**P05 已批准**：提交/批准前复核证据有效性。旧证据被停用、适用范围改变或新事实冲突时，提示影响并阻止不经确认的批准，要求重新验证受影响结论。已批准版本保留原文和历史依据并追加失效提示，是否停用由审核人留痕处理；访问权收紧立即生效，不等待重跑。

### 6.2 记忆信任 [已确认：Q18、Q34、Q43；已批准 P05]

可以保留带来源但待确认的陈述，不能当成确定事实复用。只有已确认/已审批且未过期、无未解决冲突的内容可作确定事实。审批整包并不会把其中的“待确认假设”变成事实。

**P05 已批准**：采用“确认程度”和“有效性”两个维度表示组合状态，避免一条记忆只能在已确认和已过期之间二选一。新旧相反陈述不自动覆盖，旧来源、冲突和解决依据全部保留。需要客户确认的内容由架构师录入依据，审核人可以确认批准结果中的明确结论；Agent 不能自行完成这类身份动作。

客户级复用还须具备当前用户对该客户记录及来源的权限；商机专有预算和约束不自动升格为整个客户的偏好。知识/事实变更只对新分析生效，历史快照用于解释当时依据，不保证真实模型逐字复现。

## 7. Agent、RAG 与 MCP 的已确认约束

本节是需求约束，不声明已经实现或验证。

- 显式 LangGraph：解析/意图识别 -> Supervisor/Router 计划 -> 需求、架构、产品案例证据、技术安全交付风险等专业 Agent -> 汇总 -> 一次受约束 Reflection -> 人工审阅审批 -> 发布。
- **[实现可选]** 专家按真实数据依赖并行；架构 Agent 不能依赖尚不存在的需求结果。各节点可以读取共享原始材料/计划，再由汇总阶段统一核对。具体 DAG 在技术设计中明确。
- Reflection 检查覆盖、证据与引用、风险、澄清遗漏，最多自动修订一次；前后版本保留，不允许无限修订或自改代码。
- 离线索引：解析、清洗结构化、分块、Embedding、PostgreSQL + PGVector、版本/权限/来源元数据。
- 在线检索：查询改写、权限硬过滤、向量 + BM25/关键词、RRF、Reranker、上下文裁剪、引用、流式输出。
- Reranker 超时或不可用必须可见地降级为 RRF，不应单独使任务失败；降级后仍需满足证据门禁。
- Product Catalog MCP 只读产品能力、版本、部署限制、兼容/集成；Opportunity Workspace MCP 读背景历史并执行精确批准的写入。工具和 API 均校验角色与数据范围。
- 人工中断/恢复沿用已选择的 LangGraph `interrupt()` / `Command(resume=...)`，恢复不能跳过当前身份、版本和审批校验。
- 兼容 API 的 Base URL、模型 ID 可配置，秘密仅由环境或本地配置注入；本轮不连接第三方。Langfuse/LangSmith 可沿用接入能力，但仍须满足正文和密钥不外泄边界。

## 8. 输出契约与呈现

### 8.1 输出契约 [已确认 Q10；具体字段组织已批准 P06]

JSON 是唯一内容源，Markdown/HTML 从同一内容快照渲染。这里定义必需业务字段，本次不创建机器 Schema 或代码；其编制与实现另行安排。Schema 版本号从 `1.0` 开始（P06 已批准）。

| 区块 | 必需信息 [P06] |
| --- | --- |
| identity | schema_version、客户/商机/本地任务/执行尝试/方案版本/内容修订身份 |
| provenance | 输入文档与版本、配置/提示模板版本、模型模式与实际端点标识、时间；不含密钥 |
| access | 归属、来源权限依赖、派生物访问范围；输出 JSON 也受权限检查 |
| requirements | 原始出处、需求文字、重要性、范围状态、五类覆盖结论、证据/风险/澄清关联 |
| coverage | 分母、已覆盖分子、各状态数量、业务覆盖率、需求基线身份 |
| evidence | 来源文档/版本、页码或段落/JSON 路径、片段定位、适用范围、来源类型和授权信息 |
| solution | 建议方案、部署/集成、假设和限制、交付注意事项；事实/建议/待确认明确区分 |
| risks | 类别、等级、影响、依据、缓解、责任人、接受/解决记录 |
| clarifications | 问题、关联需求、关键性、回答和来源、确认人/时间、解决状态 |
| review | 评论、退回/拒绝原因、提交快照、操作者与时间 |
| approval | 审批身份、批准快照、风险接受、允许的动作/目标/参数 |
| execution | 节点结果、失败/降级、尝试身份、Reflection 前后关联、发布逐项结果 |
| memory_updates | 拟复用陈述、来源/范围/可信与有效状态、写入结果 |

**P06 已批准**：冻结的正文内容与追加审计封套分层，内容摘要只覆盖批准的不可变部分。导出显示内容身份与审计封套的生成时间，避免后续发布结果变化被误解成篡改批准正文。

所有引用须能解析到授权来源；不存在的证据 ID、缺失章节和失配版本不能默默忽略。确实没有风险/澄清问题时用空列表和已执行检查的记录，不使用虚构条目凑完整。

### 8.2 用户可见体验 [已确认与已批准 P06]

上传区逐文件报告；运行区显示节点、失败、降级、当前模式；证据区能定位来源；审阅区可编辑草稿和查看门禁；审批区先展示快照及动作参数；导出区显著区分草稿、已批准待发布、发布完成、已替代。

**P06 已批准**：所有模式、状态标识在 JSON/Markdown/HTML 中一致；离线 Fake 输出不可冒充真实能力成果。HTML 的上传文本和模型文本按内容展示，不作为脚本/指令执行。文件中要求访问秘密、调用工具或更改权限的文字是输入数据，不是授权。

## 10. 测试与真实能力评测

### 10.1 两层证据严格分开 [已确认 Q9、Q19、Q20、Q37]

| 层 | 模型 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 工程自动化 | Stub/Fake | 状态、权限、Schema、工具契约、失败注入、幂等、恢复、演示装配 | 真实推理、需求理解、方案质量 |
| Agent 能力评测 | 显式配置真实兼容 API 或本地 LLM | 固定数据上的理解、检索证据、推理、生成、风险表现 | 生产 SLA、所有行业通用能力、零风险保证 |

工程测试必须能无 API Key 运行。真实能力评测是独立、显式启动的任务，不塞进默认 CI 或以规划自动验证名义调用收费服务。真实本地模型同样要记录身份与运行环境。

### 10.2 数据与评分规程 [已批准 P07]

- 首版按已批准的 P07 构建 30 个标注场景：10 个常规完整、5 个证据冲突、5 个缺证据/不支持、5 个关键风险、5 个需要澄清/范围调整；均在固定制造客户场景内变化，不新增行业。
- 固定拆分 10 个开发样例、20 个验收样例，覆盖上述类别；调优不得使用验收标签。另设不少于 20 个工程异常/越权/恢复用例，不用它们充当真实模型能力样本。
- 每个样例标注原子需求及出处、重要性、允许覆盖结论、相关证据集合、风险等级、允许工具动作、期望澄清、审批阻断条件。允许多个有证据的正确表达，不按字符串照抄评分。
- 在验收运行前完成标注复核并冻结数据、规则和阈值；先由人工批准基线，不根据看到的验收分数回调阈值。数据修订后升版本，不能和旧结果无说明混比。
- 需求与模型输出的一一对应由冻结标注/人工复核确认；百分比计算可确定执行，但语义是否受证据支持不能仅靠 JSON 有字段来判定。Judge 仅辅助，争议由人工裁定并保留理由。
- 每个验收样例运行 3 次（P07 已批准），分别报告三轮结果、均值、最低值和分子分母。三个重复不冒充 60 个独立业务场景。保留网络失败和重试记录，不择优丢弃失败运行。
- 能力报告记录代码/配置/数据/提示模板/模型版本与模式；提供商不暴露修订号时如实标记未知，不能承诺严格可复现。

### 10.3 首版验收门槛 [P07 已批准，不是已通过结果]

每轮验收集分别检查各指标，不用平均总分抵消失败项。所有阈值已随 v0.1 批准并冻结；变更须明确批准，不能根据验收结果事后下调。

**P07 计分细则，已批准**：下表涉及需求、证据、引用、事实、工具和风险的比例先在每个适用样例内计算，再对这些样例等权平均，作为阈值判定值；同时附列真实条目级分子分母及微平均供审计，但不混用两种口径。适用样例由黄金标注预先指定，不能根据模型有无输出来选择。无输出、超时或结构不可用的样例，其全部适用能力指标计 0，且单独计入有效响应失败；不伪造引用数量补分母。黄金要求提供证据/识别风险但模型全部省略时，对应指标计 0；黄金本就不存在此项时按不适用处理。

| 指标 | 定义/口径 | 已批准门槛 |
| --- | --- | --- |
| 有效响应率 | 返回符合黄金场景期望的有效结构化结果数 / 全部验收样例数；合理的待澄清或拒绝也可构成有效结果 | 100%；任何无输出样例不得因别项分母为空而通过 |
| 意图识别准确率 | 正确识别任务意图的样例数 / 有标注意图样例数 | >=90% |
| 需求提取召回率 | 正确匹配的黄金需求数 / 黄金需求总数 | >=90% |
| 需求提取精确率 | 正确匹配需求数 / 输出的原子需求数，重复匹配不重复计对 | >=90% |
| 覆盖结论准确率 | 对黄金需求给出正确五类状态的数量 / 黄金需求数；漏提取也算错 | >=90% |
| 检索证据命中 Hit@8 | 前 8 条检索结果至少命中一条人工相关来源的查询数 / 有相关来源查询数 | >=90% |
| 检索召回 Recall@8 | 每查询前 8 条命中的唯一黄金来源数 / 该查询全部黄金相关来源数，再取均值 | >=80% |
| 引用可定位率 | 身份、版本、定位均可解析的引用数 / 全部引用数 | 100% |
| 引用支持正确率 | 人工确认能够支持对应论断且适用的引用数 / 全部引用数 | >=95% |
| 事实证据充分率 | 需要外部依据且得到有效证据支持的事实论断数 / 全部此类事实论断数 | >=95%，关键产品承诺须100% |
| 工具选择正确率 | 满足黄金工具/参数/权限契约的决策步数 / 全部应决策步骤，含正确不调用 | >=95% |
| 风险识别召回率 | 正确识别的黄金风险数 / 黄金风险数 | >=90%；严重风险100% |
| 风险精确率 | 与黄金或人工确认有效风险对应的输出数 / 全部输出风险数 | >=80%，防止无依据堆风险刷召回 |
| 结构完整性 | 必需区块有效且内部引用一致的结果数 / 需产出方案的样例数 | 100% |
| 人工方案质量 | 可用性、证据诚实性、约束完整性、表达可读性各1-5分；保留逐项分 | 四项均值>=4，单项不得<3 |
| Reflection | 每样例四项人工质量分的等权均分，计算修订后减修订前，再对同一批适用样例平均 | 平均差>=0；不得新增严重漏检/越权/虚构承诺 |

无相关证据的负例不计入 Hit/Recall 分母，另验应明确报告不足且不编造来源。零分母显示不适用，不能当作 100%；缺少关键指标正例意味着验收集不完整。模型失败导致无输出的有效样例计失败而非删掉；环境完全不可用时报告“能力未验证”，不转 Fake 给分。

**P07 补充**：不应调用工具却调用、无真实证据却编造引用、无依据新增风险等负例错误，须单独记录，不能以该项黄金集合为空为由豁免。Reflection 主指标由人工按固定四维规则评定，Judge 只辅助；前后都有效才能计算配对差，无有效配对的样例记 Reflection 失败并阻止该轮通过，不从样本集合中消失。实际业务流程可以通过已记录的人工复核补救，但这不能回填成自动 Reflection 的能力通过。

已批准评分锚点：1=不可用/误导，2=需大修，3=需明显人工修正，4=小修可用，5=无需实质修改。内部严重风险漏检、越权、未经审批的写入、未授权绑定承诺任一出现即本次验收不通过，不能靠均分豁免。

### 10.4 工程硬门禁 [已确认原则，验收细则 P07]

要求所有已批准的工程用例通过：无权限来源不得进入两路候选、上下文、导出、记忆、轨迹或 MCP；禁止自审批；参数变更使旧批准失效；取消/旧运行不产生新副作用；重复恢复不重复写入；未知结果先核实；失败不静默切模式；密码和密钥不入日志/产物。

套件包括既有测试、领域新增测试、RAG 集成、双 MCP、审批中断/恢复、Docker smoke。若既有测试有无关基线失败，必须记录并单列处理，不能宣称全套通过。少量通过用例也不代表安全性已被数学证明。
