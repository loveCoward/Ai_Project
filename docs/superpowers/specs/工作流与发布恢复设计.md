## 1. 已批准业务边界

业务基线第4、9、11节及 P01/P04/P08 已规定：同一任务和全局最多一个活跃分析；重跑产生新的 Proposal Analysis Attempt，旧尝试不得覆盖当前候选；取消停止新调度与未发起副作用；提交、审批和外部动作绑定固定修订及精确参数；未知外部结果先核实，发布完成以全部动作成功为准。人工等待不计入主动运行期限；业务恢复须重新鉴权。本文不重新批准这些规则。

当前 `src/service/service.py` 是通用聊天入口，接受请求中的 `thread_id`/`user_id`，并依据图中断自动将消息包装为 `Command(resume=...)`。这不是售前任务、尝试或审批门禁的已实现行为。PostgreSQL checkpointer 和业务记录即使共库，也不能推定跨连接与外部工具的写入同属一个事务。

## 3. 正常与失败路径待细化

启动时：验证架构师、任务状态、输入修订和当前来源权限；同事务建立尝试、thread 映射与执行占用。运行时：在受限步骤前复核尝试代次、当前授权和取消标记；结果回写仍用预期修订及尝试身份的短事务门禁。重启/超时：先核对旧尝试、在途调用及未就绪产物，再决定释放或接管槽位，不把超时直接当成无副作用。

人工等待释放全局槽位但保留原任务的锁定快照，恢复前重新占位并验权。审核决定先经业务门禁与审计持久化，需要继续中断图时记录稳定恢复意图，再推进 checkpoint；每次重新领取递增 fencing 代次，旧领取者的迟到推进和回执拒绝。持久图状态记录消费回执，业务结果丢失后先核对 checkpoint，无法判定则不重放。外部发布逐项动作使用批准动作标识作为目标幂等键，只有可验证的目标或适配层幂等能力通过门禁时才允许写入；未知结果按原键核实，不能保证时动作不启动且发布保持未完成。领取/回执和目标端协议仍待设计。本节不表示已有可运行恢复流程。

## 4. 第十五轮确认：等待与审批

**TD-027 已确认：** 人工等待保留尝试及 checkpoint，释放全局槽位让其他任务使用；原任务锁定快照仍不得并行分析或编辑。重新认证后恢复须重新占位、复核授权和尝试，繁忙时保持等待。此阶段不新增任务或版本的业务状态。

**TD-028 已确认：** 审核决定绑定固定快照和当前权限，在短事务内持久化审批及审计；需要继续被中断的图时一并保存恢复意图，提交后才推进 checkpoint。中断节点恢复时可能从该节点开头重跑，故只读取并核对既存审批身份和快照，不在中断前重做审批或副作用。推进失败时凭既存决定对账，不重新批准或盲目重放外部动作。关联决策：[ADR-0004](../../adr/0004-approval-before-graph-resume.md)。

## 5. 第十六轮确认：恢复与写入的重试身份

**TD-029 已确认：** 同一审批决定、Proposal Analysis Attempt 及其 graph thread、固定修订和中断目标复用稳定恢复意图标识；短事务领取执行权后再推进图，图的持久状态记录该意图已处理。业务回执丢失时先核对 checkpoint，确认已处理再补记结果；没有消费标记不能证明未执行，无法判定时保持待核实，禁止盲目重复 resume。恢复需重新鉴权；失效中断或旧尝试拒绝执行，节点仍须幂等。关联决策：[ADR-0005](../../adr/0005-idempotent-graph-resume-intents.md)。

**TD-030 已确认：** 每个批准动作具有稳定标识与固定参数摘要，并直接以动作标识作为本地 MCP 目标幂等键；有界重试和恢复沿用原键，每次技术调用另有独立调用标识及结果。目标端对同键不同参数摘要拒绝且不覆盖；写入结果未知先按原键核实，禁止换键重试；改参须重新审批并创建新动作标识。关联决策：[ADR-0006](../../adr/0006-approved-action-id-as-idempotency-key.md)。

选择固定恢复意图与图内消费回执，是为了在业务回执丢失时区分可确认已处理与无法判定的状态，后者必须安全停留在待核实，避免重复推进。批准动作直接充当目标幂等键，减少单独键映射；其代价是首版本地 MCP 目标必须支持动作标识、参数摘要冲突检测及按键核实。上述为已确认的技术方向，具体执行协议与目标能力尚未完成设计或验证。
