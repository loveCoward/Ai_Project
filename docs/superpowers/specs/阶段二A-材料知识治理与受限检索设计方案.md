## 1. 目标、依赖与边界

把已登记的合法材料变成可定位证据，并让当前有权用户检索适用、已发布的知识版本。客户材料属于任务输入，不要求先走内部知识发布；内部知识候选不能因解析或索引成功就成为 Published Knowledge Version。

阶段一必须先有稳定资源身份、来源依赖、当前授权、修订、审计和文件就绪契约。本阶段增加解析、知识治理、检索及只读工具；不生成完整 Proposal Package，不创建外部任务或写入正式方案。阶段 2A 只交付只读 Product Catalog MCP；Opportunity Workspace MCP 的只读背景读取安排在阶段 2B，任何写工具留到阶段四。

**实施先后：2A-0 认证与入口隔离 → 2A-1 解析/知识审核 → 2A-2 受限检索/只读 MCP。** 登录及 JWT 接入属于本阶段开放 HTTP 前的共享前置工作，由阶段二B继续复用，不得等到2B才保护2A接口。知识审核在本阶段实现最小可用应用服务，阶段三复用其审批基础并完善交互，不要求2A依赖尚未实现的阶段三。

## 2. 工程方案与取舍

| 选择 | 推荐默认值与理由 | 备选及代价 |
| --- | --- | --- |
| 解析 | PDF 逐页提取，DOCX 按段落/表格单元定位，MD 按标题/段落，JSON 按结构路径 | 整篇纯文本转换较省事，但不满足稳定出处和表格定位；扫描件明确不支持，不增加 OCR |
| 检索 | 先物化有权且适用的块集合；PGVector 精确向量检索 + 确定性分词 BM25，RRF 合并 | 首版知识库种子规模上限为100个文档版本、5,000个有效块，先避免近似索引调参；HNSW 可在实测需要时再评估，不承诺当前性能 |
| 索引切换 | 新索引准备完毕且审核通过后，短事务切换有效版本指针 | 原地覆盖旧索引会破坏历史证据及失败恢复 |
| MCP 传输 | 由后端管理本地 stdio 子进程；2A 仅启动/注册只读 Product Catalog MCP，Opportunity Workspace MCP 只读接入属于 2B，写工具属于阶段四 | HTTP 多出网络鉴权和服务编排，暂不增加；具体锁定 SDK 的跨平台支持须验证 |

## 3. 认证与外发前置契约

三个演示账号仍是一账号一角色。建议口令验证材料及签名密钥由本地秘密配置注入，业务库只保存主体及当前授权；JWT 校验算法白名单、subject、issuer、audience、期限。访问 token 建议15分钟，无静默持久刷新；重新登录不改变已有后台尝试的权限范围。具体期限是技术默认值，后台规则沿用 TD-015。

售前 API 使用独立路由和服务依赖。售前运行配置默认不注册通用 `/invoke`、`/stream`、`/history`、`/threads`、`/agui` 和反馈外发路径；兼容脚手架演示需显式独立配置、独立 checkpoint 范围，不能读写售前 thread。业务 API 从已验证身份取 actor，不接收自报 `user_id`、数据库连接串、模型地址或 graph thread。

模型、Embedding、Reranker、Judge、观测的配置记录用途、模式、接收端别名、实际模型身份和允许数据类别。凭据单独注入；请求正文、工具输出或文档 URL 不能修改目的端。每次调用同时检查当前来源授权和外发配置；重定向不得把正文送往未配置接收端。元数据观测采用字段白名单，默认关闭正文/证据/Prompt 上传。Fake 模式使用显式确定性适配器，不能悄悄调用在线 Embedding，也不能用其结果证明语义检索质量。

## 4. 数据和来源契约

沿用阶段一资源/版本/直接依赖表；新增表名仅为建议。

| 记录 | 核心关系 | 一致性要求 |
| --- | --- | --- |
| `knowledge_documents/knowledge_versions` | 文档系列、产品/部署适用范围、资源版本、提交者、治理修订 | 不用上传时间跨产品分支替换有效版本；候选、已发布、停用各有记录 |
| `task_input_manifest` | 任务输入修订、材料版本及必需/可选/未分类标记、标记人 | 标记随输入修订留存；未分类材料不自动按可选处理 |
| `parse_jobs/parse_results` | 输入版本、文件摘要、解析器版本、逐文件结果、错误码 | 重试复用作业身份；失败不覆盖先前成功结果 |
| `source_locations/chunks` | 原文件版本、页/段/表格单元/JSON路径、文本范围、块摘要 | 块身份由程序产生；跨块引用保留原定位，不由模型编造页码 |
| `index_builds/embeddings` | 来源版本、分块/分词配置、模型身份、维度、模式、批次状态 | 不混用维度或模型；未完成构建不进入有效索引 |
| `knowledge_reviews` | 固定候选版本、提交人、审核人、决定、适用范围及索引构建 | 审核角色和禁止自审批在后端检查；批准记录追加、不覆盖 |
| `retrieval_runs` | 主体/尝试、授权范围指纹、知识目录修订、双路排名、降级记录 | 保留实际输入依赖；只读受授权轨迹，不写普通日志正文 |

知识版本审批与 Proposal Version 审批是不同对象的决定。客户材料仅登记来源声明、就绪和任务归属，不自动进入共享知识。种子中的演示知识也须有明确的合成标记和可追溯的审核记录；初始化不能绕过发布规则或重启复活停用版本。工程 fixture 可构造审核完成状态，但不把该 fixture 宣称为实际发布记录。

知识当前有效性按文档系列及产品/部署适用范围确定。同一文档系列中，适用范围有重叠且可能同时命中的候选不得由上传时间、版本号或检索排序自动择一；发布前须由审核人显式调整适用范围或确认替换关系，确保每个查询范围只有一个可确定的当前有效版本。范围冲突未解决时阻断该候选发布和相关检索，不回退到任意旧版。

### 4.1 知识规模统计口径

以下为落实 P08 的工程计数口径，两个上限分别检查，不把文档系列、内容版本、索引构建和分块混为同一对象：

- 文档版本数按当前演示知识库中已登记的不同 `knowledge_version_id` 计数，上限100；候选、已发布、被替换和停用版本均计入。相同版本重新解析或重建索引不新增文档版本，客户任务材料不计入共享知识版本数。达到上限后拒绝新增知识版本，不通过删除历史或把新内容登记为旧版本腾出名额。
- 有效块数按当前生效目录指向的完整索引构建中不同块ID计数，上限5,000；不因某读者无权限而减少全库计数。停用/被替换版本的历史块和未激活的构建不计入有效块；同一知识版本仅能有一个当前有效构建。
- 新构建前核对文档版本数、候选分块数及预期切换后的有效块总数。替换时从预期总数扣除将退出有效目录的旧块，再加入新块；保留的旧文件和索引仍供受限审计。单批候选块也不得超过5,000，暂存构建受单批期限及显式失败状态约束。
- 发布/索引切换的短事务锁定目录修订，重新检查切换后计数、适用范围和预期修订。两个并发批次不能各按旧计数通过；冲突返回后重新核定。超限保留旧有效目录并报告实际计数，不静默裁块。

## 5. 解析、索引和发布协议

1. 验证来源声明、当前权限、扩展名与文件内容类型、阶段一 readiness 和摘要。检查10文件、20 MiB单文件、50 MiB单任务上限；拒绝加密/损坏/不支持内容并逐文件报错。售前架构师在任务输入清单中逐份标记 Customer Material 为必需或可选；未分类材料的解析失败保持待人工分类/补充，不能将输入集判为完整，也不能由模型自行降为可选。DOCX 解压限制条目数与展开大小，禁止解析外部实体或跟随文档链接取网。
2. 在受控子进程执行解析，单文件60秒；终止超时进程并保留失败证据。分别检查100,000/300,000 Unicode字符上限，不通过截掉需求假装成功。扫描PDF/无可提取文本明确待人工处理，不启动 OCR。
3. 保存不可变解析结果和直接依赖；必需材料解析失败则对应任务保持待补充，可选材料失败时保留其余有效结果并明确列出未使用来源；未分类材料失败则输入集保持未解决，不得标记为完整。块的分割、重叠和中文分词配置版本化；初始建议约600 token/80 token重叠，并保留段落和表格边界，真实配置需按模型容量核定。
4. 独立索引作业在数据库事务外调用已配置 Embedding，单请求60秒、单批10分钟，技术错误初次后最多2次且不重置总期限。开始构建前按第4.1节检查知识规模，超限拒绝新索引批次；事务内登记完整批次和来源后才可标记索引可用。
5. 架构师提交固定知识版本，审核人独立发布/替换/停用。最终短事务同时检查当前授权、候选修订、索引完整、适用范围无冲突及第4.1节的规模条件，再保存审核决定、有效指针与审计；索引构建失败或发布后将超出规模上限时拒绝切换并保留原有效版本。
6. 停用立即影响新检索；目录修订失效相关缓存。阶段2A保存知识变化事件（版本身份、变化类型、前后适用范围、目录修订、操作者、时间和原因）及可反向追溯的来源关系，保留旧版本及出处供受限审计。固定方案提交/审批时的证据复核、受影响结论提示和已批准历史方案的失效提示由阶段三实现；任何阶段均不能改写历史批准内容。

## 6. 双路检索和权限闭包

检索接受可信主体或 Attempt 上下文、任务、查询、产品/部署范围及配置版本，返回稳定 evidence ID、来源版本/定位、分数与可见降级信息。Attempt 的范围上限必须与当前授权取交集；扩大授权不能扩大旧尝试。

数据库先限定已发布且适用的知识版本及有权资源/来源闭包，再物化允许块。向量路只在该集合计算距离；关键词路只对同一集合构造临时 BM25 语料及统计。未经授权块不能进入应用候选、RRF、Reranker、模型或轨迹，不能先全库 top-k 再过滤。显式任务材料是另一个输入集合，不把它误标为已发布知识。

建议两路各取20个候选，以块ID去重并采用 RRF，常数默认60；保留前8条作为 Hit@8/Recall@8 的可审计结果，再按预算裁剪模型上下文。精排3秒超时立即使用已得 RRF 顺序并显示降级；不能因精排失败跳过内容门禁。相同分数按稳定ID排序。参数是待验证起点，基线没有批准其效果。

缓存键包括主体、有效权限范围、全局授权修订、目录修订、适用范围、查询和所有检索配置版本。缓存命中后仍重新验权及检查就绪；当前权限变化不得复用旧候选。检索完成/外发前再验证目录和授权修订，必要时重算或明确失败；不得用长事务包住外部模型调用。

查询改写只能生成检索语句，不能生成执行权限、工具名称或地址。上下文预算不足时明确报告缺失材料/范围；不能把只看了部分关键需求的结果标记为完整分析。

## 7. 接口和只读 MCP

| 建议应用契约 | 主要输入/输出 | 权限和失败 |
| --- | --- | --- |
| `parse_material` / `get_parse_result` | material version、request ID → job/result IDs、逐文件状态 | 架构师及资源范围；未就绪、超限、不支持分别表达 |
| `submit_knowledge` / `decide_knowledge` | expected revision、固定版本、决定/原因 → review ID | 架构师提交、审核人决定；不接受 Agent 审批 |
| `retrieve_evidence` / `read_evidence` | query、范围、可信上下文 → evidence IDs/片段/定位 | 每次当前授权，未知或无权对象统一不泄露响应 |
| Product Catalog MCP `lookup_capabilities` | 产品/版本/部署条件 → 已发布能力及 evidence IDs | 仅只读；候选/停用/越权来源不能返回 |
| Opportunity Workspace MCP `read_context`（2B） | 已授权 Opportunity → 背景/历史及来源 | 只读背景接入2B；写工具到阶段四才注册；2A 不启动或注册此服务 |

Agent 仅能提供业务查询参数。后端为工具注入短期、指定 audience 的服务调用凭证及有界上下文，MCP 通过共享授权组件读取当前主体/Attempt记录并重建有效范围；不信任模型给的 actor、grant 或声明为 approved 的字段。凭证不进入 Prompt、checkpoint、业务参数摘要或普通日志。stdio 子进程只继承必要配置，不复制全套宿主秘密。

Product Catalog MCP 是共享材料知识应用服务的只读适配器，调用方向为：业务入口 → 受控 MCP 客户端 → stdio 工具适配器 → 共享 `retrieve_evidence` / `read_evidence` 应用服务 → 统一授权组件及持久层。共享服务以同一 Python 包运行在后端或 MCP 进程中，MCP 不回调自身，也不通过另一个无认证 HTTP 入口取数据。两种入口读取同一知识目录和来源关系，不维护独立产品事实库、独立 ACL 或未过滤的检索结果缓存；合成产品目录同样遵守知识发布规则。

`lookup_capabilities` 将产品/版本/部署条件映射为共享服务的受限查询，固定 `source_scope=published_knowledge`，不能读取任务材料、候选或停用版本。MCP 传输封装在工具业务参数之外携带可信调用上下文；验证凭证后构造 actor/范围，使用与业务 API 相同的角色、当前授权、来源闭包、适用性、readiness 和返回前修订复核。片段与定位统一经 `read_evidence` 或其同一内部读取组件取得；工具不得直接查询向量表、打开文件或依赖父进程已验权而跳过复核。

阶段2A的交互查询只需当前已验证主体和有界任务/产品范围，不创建虚构的 Analysis Attempt。阶段2B接入后台分析时，复用相同服务并从服务端 Attempt 记录重建启动范围上限与当前授权的交集；客户端传入 Attempt ID 不构成调用权限。

Product Catalog MCP 只读调用遵守 P08 的单动作10秒期限和有界重试；超时、调用失败与成功但无匹配结果使用不同结果状态，不能把失败伪装成空结果。文件、字符、索引、Embedding、精排及 MCP 的适用上限均可配置，运行记录实际配置值；这些值是首版演示边界，不代表已测性能或生产 SLA。
