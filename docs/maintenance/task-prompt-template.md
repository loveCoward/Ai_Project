# 通用任务提示词模板

适用：在本仓库（企业 AI 售前方案工作台）向编码助手派发任意任务时复用。
用法：复制「核心块」，按任务类型从「附加段」挑 1 段追加，填满 5 个槽位（模式 / 目标 / 范围 / 证据类型 / 完成判据），其余保留原文。

---

## 一、核心块（每次必带）

```text
【模式】执行 / 只分析 / 只审查（三选一，模板默认执行）

【角色与边界】
你是本仓库的资深工程师，只做本次范围内改动：不扩大范围、不顺手重构无关文件、不改用户未提交的改动。
结束时必须交付：改动文件清单 + 实际验证结果 + 未完成项及原因。

【事实基线（开工前必须做，不得跳过）】
1. 读 AGENTS.md、CLAUDE.md；涉及业务对象/状态时读 GLOSSARY.md；涉及阶段进度读 STATUS.md。
2. 跑 git status --short、git log --oneline -5，先报告工作区状态；有未提交改动先说明，不覆盖、不 stash、不 reset。
3. 只以当前代码与测试结果为准；README/交付记录/目录结构里的规划描述不算已实现能力。
4. 计划中“拟新增”的路径、命令、入口，若实际不存在即记为“未就绪”，不临时自造第二套。

【任务】
目标：【一句话说清可观察的结果，不写手段】
范围：【目录/文件/路由/任务编号；明确到可 grep】
前置条件：【已具备的事实；缺什么就写阻塞，不假装前置已完成】
参考模式：【要仿写的现有文件路径】

【硬约束】
- 业务规则以 docs/superpowers/specs/初版业务需求分析文档.md 及决策记录为准；需要改规则时先记变更并取得确认，不在代码或测试里悄悄改写基线。
- 权限、来源过滤、派生物边界、审批、状态转换、幂等、恢复：只能收紧不能放宽；不得只靠前端隐藏按钮实现。
- 证据分层：离线 Fake、真实 PostgreSQL、真实模型、真实浏览器分别取证，互不替代；不得用 SQLite / Fake / 跳过用例制造通过。
- 真实模型调用、外部写入、发布、部署：未显式授权一律不执行。
- 不读不写真实客户敏感材料、.env、privatecredentials、token 或其它秘密。
- 不删除失败样例、不缩小测试范围、不改阈值来让测试变绿。

【产出】
1. 改动：【文件路径】——【一句话作用】
2. 测试：新增/修改【用例路径】，覆盖【正常 / 失败 / 权限 / 幂等 / 恢复 中的哪些】
3. 验证（按改动范围选取，逐条给真实输出结论）：
   uv run pytest 【范围】 -q
   uv run ruff check && uv run ruff format --check
   uv run pyrefly check
   前端改动另跑：cd frontend && npm run typecheck && npm run build
   涉及 PostgreSQL 门禁：uv run python scripts/test_presales_postgres.py --pg-bin "<bin>" --check-vector
   涉及文档：.venv/Scripts/pymarkdown.exe scan 【文件】
4. 范围说明：实际完成 / 明确未做 / 未验证项及原因。
5. 不确定处标注“未核实”，不推测、不编造测试数字；引用历史结果须注明“历史结果”。

【不做】
- 【明确排除项：不改的表结构、不动的路由、不扩的模块、不引入的依赖、不碰的阶段】

【完成判据】
【可观察的通过条件，例：tests/presales 全绿 + 越权用例返回 403 + 页面能渲染终态 + 迁移可升降级】
```

## 二、附加段（按任务类型挑一段追加到核心块之后）

| 任务类型 | 追加内容 |
|---|---|
| 新增功能 | `先给 3—8 条实现要点与文件落点再动手；契约/接口先定，再写测试，再实现；新接口须给请求/响应示例与失败语义。` |
| 修 Bug | `先写能复现失败的最小测试并确认它红；再改到绿；说明根因（不是现象）与同类隐患是否已排查；不得靠放宽断言修复。` |
| 重构 | `行为不变，先跑基线测试记录结果；分步提交，每步可独立通过；不夹带功能改动、不顺手改名无关符号。` |
| 只审查 | `只读不写。按【阻断/应修/建议】分级，每条给文件:行号、后果、最小修法；不评论风格偏好，不重复计划已知事项。` |
| 文档/交付记录 | `只写已核实事实；规划、目标、历史数字必须标注状态与来源；不复制整份需求文档；表格优先，避免与 GLOSSARY.md 用词冲突。` |
| 依赖/迁移/环境 | `先给影响面（版本、兼容、回滚、其它模块引用）再动手；迁移只新增不改历史；失败必须可回退，且给出验证命令。` |
| 并行/worktree 规划 | `只分析不执行。先核 git worktree list / branch -a / HEAD，再按依赖波次给表：worktree 名、分支、基线、任务号、共享文件独占声明、环境独占项（PG 实例与端口、uvicorn 端口、.venv、node_modules、checkpoints.db）、合并顺序、退出证据。并行数以共享文件冲突可控为限，禁止按任务数 1:1 建。` |
| 真实环境取证 | `先确认授权与环境身份（PG 版本/角色、模型端点、浏览器），再执行；失败按原样记录并保留，不切换 Fake 重跑充数；报告须含环境指纹、命令、原始输出、失败分类。` |

## 三、模型路由（编码助手，与产品内真实模型调用无关）

| 任务性质 | 建议模型 | 理由 |
|---|---|---|
| 契约/Schema/DTO、迁移与索引、事务与提交边界、fencing、取消与排空、恢复对账、并发竞态、门禁判定、终态竞争 | ChatGPT 6.1 Sol | 需要长上下文一致性与反例推理，出错代价高且难靠测试兜住 |
| 已定契约下的实现、Fake/fixture、样例数据、DTO 导出脚本、报告与文档排版、类型与构建修复、重复性测试补齐 | DeepSeek V4.1 Flash | 输入输出边界清晰、可被测试与 review 兜住 |
| 四专家节点、SSE/前端运行页、探针准备 | Flash 起草 + Sol 复核 | 改动面广但语义明确，复核卡住边界 |

> 判定顺序：先问“错了是否会被测试兜住、是否会污染后续任务的基线”。兜不住且影响面向后传导 → 强推理档；兜得住且边界已由契约固定 → 快档。
> 若引入第三档（如 Sol / Luna / Flash 三档），按同一规则切分：语义明确但有状态与持久化耦合的工程实现放中间档，纯展示与样板链尾放快档。
> 两个模型的能力判断目前基于任务性质推断，未经本项目实测；若某类任务出现反复返工，先换模型再改流程。

## 四、精简版（熟手 / 小任务）

```text
【执行】只改【范围】。先读 AGENTS.md 并跑 git status；只信代码与测试。
目标：【可观察结果】。约束：权限/来源/幂等只收紧；离线≠真实PG≠真实模型≠浏览器；无授权不调真实模型。
产出：改动清单 + pytest/ruff/pyrefly（前端加 typecheck+build）真实结论 + 未完成项。不做：【排除项】。
不确定处标“未核实”，不编数字。
```

## 五、常见失效点

| 现象 | 原因 | 补哪一段 |
|---|---|---|
| 模型直接改了一大片无关文件 | 缺「模式/范围/不做」 | 核心块 角色与边界 + 不做 |
| 把计划里的“将实现”当已完成 | 缺事实基线与证据分层 | 核心块 事实基线 + 证据分层 |
| 报“测试全部通过” | 未要求真实输出与范围说明 | 核心块 产出 3/4 |
| 并行方案落地就撞车 | 未要求核现状与共享文件独占 | 附加段「并行/worktree 规划」 |
| 用 SQLite/Fake 冒充真实门禁 | 未写死证据分层 | 核心块 硬约束第 3 条 |
